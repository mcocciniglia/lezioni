Il problema dei 5 filosofi

Concorrente: risorse condivise, deadlock, starvation e una soluzione con semafori (Java).

TPSIT • Classe quarta • 1 ora

Obiettivo della lezione

  • Capire perché alcuni programmi concorrenti possono bloccarsi (deadlock).
  • Riconoscere il rischio di starvation (uno aspetta “troppo”).
  • Implementare una soluzione in Java usando Semaphore.

Scenario (modello)

  • Ci sono 5 filosofi seduti in cerchio.
  • Tra ogni coppia di filosofi c’è una forchetta (totale 5).
  • Per mangiare servono 2 forchette: sinistra + destra.
  • Ogni filosofo ripete: pensa → prende 2 forchette → mangia → rilascia.

Mappatura informatica

  • Filosofo = thread
  • Forchetta = risorsa condivisa (mutex / semaforo binario)
  • Prendere = acquire(), rilasciare = release()

Soluzione “ingenua” e deadlock

Se tutti fanno: “prendo la sinistra, poi la destra”, può accadere che:

  1. Tutti prendono la forchetta sinistra (ok).
  2. Tutti aspettano la destra… ma la destra è già presa dal vicino.
  3. Nessuno rilascia (perché sta aspettando). Risultato: deadlock.
Le 4 condizioni del deadlock (Coffman)
  • Mutua esclusione: una forchetta la usa un filosofo alla volta.
  • Hold and wait: tengo una forchetta e aspetto l’altra.
  • No preemption: non posso “strappare” una forchetta a qualcuno.
  • Attesa circolare: l’attesa forma un anello.

Soluzione pratica: “maggiordomo” (N−1)

Aggiungiamo un semaforo globale con 4 permessi (se i filosofi sono 5). Prima di prendere le forchette, un filosofo deve ottenere il permesso dal maggiordomo.

Perché funziona? Se al massimo 4 filosofi provano a prendere forchette, non può succedere che 5 tengano ciascuno una forchetta e aspettino l’altra: almeno uno troverà una coppia disponibile e potrà mangiare, “sbloccando” gli altri.

Codice Java (base)

import java.util.concurrent.Semaphore;

public class DiningPhilosophers {
  static final int N = 5;

  public static void main(String[] args) {
    // Forchette: semafori binari (1 permesso). true = fairness (FIFO) quando possibile.
    Semaphore[] forks = new Semaphore[N];
    for (int i = 0; i < N; i++) forks[i] = new Semaphore(1, true);

    // Maggiordomo: N-1 permessi
    Semaphore waiter = new Semaphore(N - 1, true);

    for (int i = 0; i < N; i++) {
      int left = i;
      int right = (i + 1) % N;
      new Philosopher(i, left, right, forks, waiter).start();
    }
  }

  static class Philosopher extends Thread {
    private final int id, left, right;
    private final Semaphore[] forks;
    private final Semaphore waiter;

    Philosopher(int id, int left, int right, Semaphore[] forks, Semaphore waiter) {
      this.id = id;
      this.left = left;
      this.right = right;
      this.forks = forks;
      this.waiter = waiter;
      setName("Philosopher-" + id);
    }

    @Override public void run() {
      try {
        while (!isInterrupted()) {
          think();

          waiter.acquire();              // chiede permesso al maggiordomo
          forks[left].acquire();         // prende sinistra
          forks[right].acquire();        // prende destra

          try {
            eat();
          } finally {
            forks[right].release();
            forks[left].release();
            waiter.release();
          }
        }
      } catch (InterruptedException e) {
        interrupt();
      }
    }

    private void think() throws InterruptedException {
      System.out.println(getName() + " pensa...");
      Thread.sleep(200);
    }

    private void eat() throws InterruptedException {
      System.out.println(getName() + " MANGIA ✅");
      Thread.sleep(200);
    }
  }
}
Tip: cosa osservare in output
  • Il programma continua a stampare “pensa/mangia” senza fermarsi.
  • Non si deve mai bloccare tutto insieme (deadlock).
  • Con fairness=true si riduce il rischio che uno mangi pochissimo.
