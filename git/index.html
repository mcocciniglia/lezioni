Introduzione a Git

Perché usare un sistema di controllo versione e come iniziare con i primi comandi.

Durata: 1 ora Modalità: guidata + pratica Consegna: Classroom

Obiettivo della lezione

Capire a cosa serve Git, perché è utile nello sviluppo software e realizzare il primo repository locale usando pochi comandi essenziali.

Il problema: troppe versioni dello stesso file

Prima di parlare di Git, osserviamo una situazione molto comune.

progetto.html
progetto_finale.html
progetto_finale2.html
progetto_finale_vero.html
progetto_corretto.html
progetto_corretto_definitivo.html

Domande

  • Qual è la versione corretta?
  • Chi ha modificato il file?
  • Quando è stata fatta una modifica?
  • Se il progetto non funziona più, come torno indietro?
  • Come lavoro insieme ad altri senza sovrascrivere il lavoro altrui?

Che cos'è Git?

Git è un sistema di controllo versione. Serve a registrare la storia di un progetto: modifiche, autori, date e motivazioni dei cambiamenti.

Non è semplicemente un modo per “salvare file”: Git permette di costruire una cronologia ordinata dello sviluppo di un progetto software.

Perché Git è spendibile?

Git è uno strumento usato nel mondo del lavoro. È presente nello sviluppo web, nello sviluppo software, nei progetti open source, nella cybersecurity, nell'automazione, nel DevOps e nello sviluppo di applicazioni.

Conoscere Git significa saper lavorare in modo più ordinato, professionale e collaborativo.

In pratica, Git permette di:

  • tenere traccia delle modifiche;
  • recuperare versioni precedenti;
  • lavorare in gruppo;
  • sperimentare senza paura di perdere il lavoro;
  • presentare meglio i propri progetti personali.

Git e GitHub non sono la stessa cosa

Git

È il programma che gestisce le versioni del progetto anche sul proprio computer.

GitHub

È una piattaforma online che può ospitare repository Git e facilitare la collaborazione.

In questa prima lezione lavoreremo solo in locale, cioè sul computer del laboratorio.

Parole chiave

Repository
La cartella del progetto controllata da Git.
Commit
Un salvataggio significativo della situazione del progetto in un certo momento.
Working directory
La cartella in cui stiamo modificando i file.
Staging area
La zona in cui prepariamo le modifiche prima del commit.

Attività pratica guidata

Apri il terminale nella cartella di lavoro e segui i passaggi.

  1. Controlla se Git è installato

    git --version

  2. Crea una cartella per la prova

    mkdir prova-git
cd prova-git

  3. Inizializza il repository

    git init

    Da questo momento Git può iniziare a controllare la cartella.

  4. Crea un file

    echo "Prima prova con Git" > appunti.txt

  5. Controlla lo stato

    git status

    Git mostra quali file sono nuovi, modificati o pronti per essere registrati.

  6. Aggiungi il file alla staging area

    git add appunti.txt

  7. Crea il primo commit

    git commit -m "Primo commit"

  8. Visualizza la cronologia

    git log

Possibile errore al primo commit

Se Git chiede nome ed email, configurali con questi comandi:

git config --global user.name "Nome Cognome"
git config --global user.email "nome.cognome@example.com"

In laboratorio può essere opportuno usare una mail scolastica o un indirizzo indicato dal docente.

Comandi essenziali della lezione

git init

Crea un nuovo repository Git nella cartella corrente.

git status

Mostra lo stato dei file: nuovi, modificati o pronti per il commit.

git add

Prepara uno o più file per il prossimo commit.

git commit

Registra una versione significativa del progetto.

git log

Mostra la cronologia dei commit.
