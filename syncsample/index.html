Java — Oggetto monitor e synchronized

Capire il “lucchetto” (monitor) di un oggetto e perché due metodi synchronized sullo stesso oggetto si bloccano a vicenda.

1) Che cos’è l’oggetto monitor?

In Java ogni oggetto può essere usato come monitor, cioè come un lucchetto. Quando un thread “prende il lucchetto” di un oggetto, gli altri thread che vogliono lo stesso lucchetto devono aspettare.

Idea semplice

Un oggetto = una chiave.
Se due thread vogliono entrare in due sezioni di codice che usano la stessa chiave, entrano uno alla volta.

2) Cosa significa synchronized su un metodo?

Se scrivi un metodo di istanza così: 

public synchronized void m1() {
  // ...
}

è equivalente (concettualmente) a:

public void m1() {
  synchronized (this) {
    // ...
  }
}

Quindi: “usano this” significa…

Il lucchetto usato è proprio l’oggetto corrente, cioè this. Se due metodi synchronized stanno nella stessa istanza, condividono la stessa chiave.

3) Domanda chiave

Se thread1 entra in m1() (che è synchronized) su un oggetto A, un altro thread può entrare in un altro metodo synchronized dello stesso oggetto?

✅ No. Perché entrambi i metodi chiedono la stessa chiave (il monitor di this).

Mini-esempio (solo per capire) 
A a1 = new A();
A a2 = new A();

// a1 e a1: stesso oggetto => stesso monitor => si bloccano
new Thread(() -> a1.m1()).start();
new Thread(() -> a1.m2()).start();

// a1 e a2: oggetti diversi => monitor diverso => possono andare insieme
new Thread(() -> a1.m1()).start();
new Thread(() -> a2.m2()).start();

4) Esercizio (output “a blocchi”)

Hai un oggetto A con due metodi m1() e m2(). Due thread partono insieme: uno chiama m1(), l’altro chiama m2().

Obiettivo

L’output deve risultare a blocchi (niente righe mescolate). Quindi o finisce completamente m1() e poi parte m2(), oppure il contrario.

  1. Esegui il codice “così com’è”: vedrai le righe mescolate.
  2. Modifica solo la classe A.
  3. Scopo: m1() e m2() devono usare la stessa chiave.

5) Codice scheletro (copia/incolla)

Incolla in un file chiamato MonitorExercise.java.

public class MonitorExercise {

    public static void main(String[] args) throws InterruptedException {
        A a = new A();

        Thread t1 = new Thread(() -> a.m1(), "T1");
        Thread t2 = new Thread(() -> a.m2(), "T2");

        t1.start();
        t2.start();

        t1.join();
        t2.join();

        System.out.println("\nFINE PROGRAMMA");
    }

    static class A {

        // TODO (OBIETTIVO):
        // Fai in modo che m1() e m2() NON si intersechino (niente interleaving).
        // Suggerimento: devono usare LO STESSO lucchetto.

        public void m1() {
            System.out.println(">>> m1 START (" + Thread.currentThread().getName() + ")");
            for (int i = 1; i <= 8; i++) {
                System.out.println("[m1] step " + i);
                sleep(120);
            }
            System.out.println("<<< m1 END (" + Thread.currentThread().getName() + ")");
        }

        public void m2() {
            System.out.println(">>> m2 START (" + Thread.currentThread().getName() + ")");
            for (int i = 1; i <= 8; i++) {
                System.out.println("[m2] step " + i);
                sleep(120);
            }
            System.out.println("<<< m2 END (" + Thread.currentThread().getName() + ")");
        }

        private static void sleep(long ms) {
            try {
                Thread.sleep(ms);
            } catch (InterruptedException e) {
                Thread.currentThread().interrupt();
            }
        }
    }
}
Attenzione (cosa NON deve succedere) 
[m1] step 1
[m2] step 1
[m1] step 2
...

[m1] step 8
<<< m1 END (T1)
FINE PROGRAMMA

💡 Suggerimento (nascosto)

Usalo solo dopo 5 minuti di tentativi.

Due metodi devono usare lo stesso monitor. Un metodo synchronized di istanza usa il monitor di this.

Quindi la soluzione più semplice è rendere m1() e m2() synchronized. 

public synchronized void m1() { ... }
public synchronized void m2() { ... }
