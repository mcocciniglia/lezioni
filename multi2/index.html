Stampante condivisa — Scheletro classi

Obiettivo: gestire coda limitata senza busy waiting

📌 Istruzioni

  • Non cambiare i nomi delle classi e dei metodi.
  • Completa solo le parti TODO.
  • Non usare busy waiting (no cicli vuoti per “aspettare”).
  • Il programma deve funzionare anche se eseguito molte volte (ordine casuale).

🧠 Suggerimento (senza spoiler)

Qui servono due cose:

  • Mutua esclusione sulla risorsa condivisa (la coda)
  • Attesa condizionata: a volte un thread deve aspettare una condizione (coda piena / coda vuota)
Domanda da tenere a mente

Quando la coda è piena/vuota: chi si ferma? e chi lo risveglia?

class UserClient implements Runnable {

    private final String name;
    private final SpoolerMonitor spooler;

    UserClient(String name, SpoolerMonitor spooler) {
        this.name = name;
        this.spooler = spooler;
        new Thread(this, "User-" + name).start();
    }

    @Override
    public void run() {
        try {
            // invio casuale
            Thread.sleep((int)(Math.random() * 2500));

            int pages = 1 + (int)(Math.random() * 12);
            PrintJob job = new PrintJob(name, pages);

            spooler.submit(job);
            System.out.println(Thread.currentThread().getName()
                    + " -> inviato: " + job
                    + " | in coda: " + spooler.getQueueSize());

        } catch (InterruptedException e) {
            Thread.currentThread().interrupt();
        }
    }
}

class PrinterDevice implements Runnable {

    private final SpoolerMonitor spooler;

    PrinterDevice(SpoolerMonitor spooler) {
        this.spooler = spooler;
        new Thread(this, "Printer").start();
    }

    @Override
    public void run() {
        try {
            while (true) {
                PrintJob job = spooler.take();

                System.out.println("Printer -> stampa: " + job
                        + " | in coda: " + spooler.getQueueSize());

                // tempo stampa proporzionale alle pagine
                Thread.sleep(job.pages * 250L);

                spooler.onPrinted(job);
            }
        } catch (InterruptedException e) {
            Thread.currentThread().interrupt();
        }
    }
}

public class Laboratorio {
    public static void main(String[] args) {

        // capienza volutamente piccola per forzare attese
        SpoolerMonitor spooler = new SpoolerMonitor(3);

        new PrinterDevice(spooler);

        // burst di utenti (più della capienza)
        new UserClient("Mario", spooler);
        new UserClient("Giulia", spooler);
        new UserClient("Luca", spooler);
        new UserClient("Anna", spooler);
        new UserClient("Paolo", spooler);
        new UserClient("Sara", spooler);
    }
}
Vincoli tecnici obbligatori
  • Non usare Thread.sleep() per “risolvere” la sincronizzazione.
  • Non usare cicli vuoti tipo while(queue.size()==0){}.
  • Se usi attesa/risveglio, ricordati che una condizione va controllata in un while, non in un if.
Output atteso (a grandi linee)

I messaggi devono mostrare invii e stampe in ordine “variabile”. Però non devono mai comparire situazioni impossibili (coda negativa, coda oltre capienza, job duplicati).
